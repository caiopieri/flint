Flint Design System

A human-readable mirror of docs/design.md. The canonical token source is docs/design/tokens/tokens.json; this page presents it for review.

Overview

Flint is a local-first note-taking app. Its interface descends from the icon: a warm dark field, a faceted stone, and restrained amber sparks. The chrome recedes so the user’s writing remains the brightest thing on screen.

Two engines share one visual identity: SwiftUI chrome and CodeMirror in a WKWebView. Use generated tokens on both sides of the seam; never introduce one-sided colors, sizes, or type.

Dark mode is primary. In light mode, amber text uses accent-text (spark-800) for accessible contrast; spark-500 remains suitable for fills, icons, and the cursor.

Reading is the core surface. The editor uses an editorial serif at a comfortable measure of 68ch. Hierarchy comes from weight and size, not decorative color.

Layout and depth

Use the 4pt spacing grid: 4, 8, 12, 16, 24, 32, 48, and 64px. Establish depth with warm surface planes and hairline borders, not theatrical shadows. Outer containers use continuous 6/10/16/22px corners; the editor and ink canvas remain square.

Raised surface
Cards, chips, and popovers use surface-raised plus a border.
Ink canvas
Paper stays light in either app theme. Rules and dots use paper-rule.

Components

  • Primary button: amber, maximum one per view, at least 44pt high.
  • Secondary button: raised surface with a hairline border.
  • Sidebar: selected row gets a raised surface plus a 2px amber leading bar.
  • Editor: bg, reading serif, amber cursor, translucent amber selection.
  • Ink embed: thumbnail on a raised surface, with a muted pencil.tip affordance.

Rules

  • Use semantic tokens, never raw hex values in product code.
  • Keep amber rare: it marks action and current location.
  • Honor Dynamic Type, zoom, and Reduce Motion.
  • Verify SwiftUI and CodeMirror render the same token values.
